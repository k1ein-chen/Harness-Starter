# 目标定义规则 — 详细指南

> CLAUDE.md 中保留了 4 项硬性要求的 checklist。
> 本文档提供详细的示例和说明。

## 四项硬性要求

### 1. 可被机器验证

目标必须能用自动化命令验证，不能依赖主观判断。

```
✅ "test/auth 下所有测试通过，tsc --noEmit 零报错，lint 零违规"
❌ "帮我把这个功能做好"
```

### 2. 含边界条件

明确什么能做、什么不能做，防止 Agent 走捷径。

```
✅ "测试全过，且不得删除或修改已有测试用例"
❌ "测试全过"（Agent 可能删测试来"通过"）
```

### 3. 有失败降级方案

设置停止条件，防止无限重试烧 token。

```
✅ "连续 3 次验证未通过 → 停止并汇报，而非无限重试"
❌ "直到做完为止"（没有停止条件的 loop 是烧钱机器）
```

### 4. 目标分层

区分长期目标和本轮目标，避免一次塞太多。

```
长期目标：这周完成用户认证模块
本轮目标：修通 auth 目录下的 3 个失败测试
```

## 完整输出格式参考

```
目标：修复 API 鉴权失败问题
完成条件：
  ✅ test/auth/*.test.ts 全部通过（npm test auth）
  ✅ tsc --noEmit 零报错
  ✅ 不修改现有测试用例
边界：不得删除或禁用已有测试
降级：3 轮尝试未通过则停止并列出失败项
```
