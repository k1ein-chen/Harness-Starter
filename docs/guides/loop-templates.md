# Loop 场景模板

Harness Starter 具备所有 loop 零件。以下是三个拿来即用的组装模板。

---

## 模板 1：每日健康巡检

自动检查项目健康状态，每天一次。

### 一句话启动

```
/loop 24h "每日健康巡检"
```

### 完整定义

```
目标：项目健康状态自动巡检
完成条件：全部检查项通过（无告警则无事，有告警则汇报）
边界：不修改任何文件
降级：连续 7 天无进展则暂停

步骤：
1. 跑 node scripts/check.mjs，记录结果
2. 跑 node scripts/gc-scan.mjs --json，检查关键告警
3. 检查 git 未提交文件数，超过 10 则提示
4. 检查 docs/handovers/ 下最新的交接卡
5. 写入 .claude/loops/STATE.md 更新状态
6. 有异常 → 输出摘要到控制台
   一切正常 → 静默结束
```

### 适用场景

- 每天上班前看一眼项目是否健康
- 团队项目多人修改后的自动化检查

## 模板 2：PR 自动 babysit

自动监控和修复 PR 问题。

### 一句话启动

```
/loop 30m "帮我 babysit 所有 PR"
```

### 完整定义

```
目标：自动处理 PR 上的 CI 失败和新评论
完成条件：所有 open PR 的 CI 通过，且评论全部处理完毕
边界：不强制 push，不关闭他人 PR
降级：某个 PR 连续 3 次修复失败 → 标记 needs-human 并跳过

每轮步骤：
1. 读取仓库所有 open PR 的状态（gh pr list）
2. 对每个 PR：
   a. 检查 CI 状态
   b. CI 失败 → 创建独立 worktree → 派 sub-agent 修复
      → sub-agent 改完后 verify-goal 验证 → 通过则 push
   c. 有新 review 评论 → 派 sub-agent 处理
      → 处理完后标记评论已回应
3. 更新状态记录到 .claude/loops/STATE.md
4. 本轮所有 PR 处理完毕，等待下一轮
```

### 所需配置

- GitHub CLI (`gh`) 已登录
- 项目有 CI 配置（GitHub Actions 等）
- 建议配合 `isolation: worktree` 防止并行冲突

### 适用场景

- 维护多个活跃 PR 的项目
- 需要快速响应 CI 失败的团队

## 模板 3：自我进化循环

定期分析项目问题趋势，自动推动改进。

### 一句话启动

```
/loop 7d "自我进化"
```

### 完整定义

```
目标：分析项目健康趋势，自动改进
完成条件：输出一份改进提案，你批准后执行
边界：不自动修改任何文件，仅生成提案
降级：连续 2 次无新发现 → 把间隔拉长到 14 天

每轮步骤：
1. 扫描 .claude/reviews/ 下所有审查报告
2. 分析问题类型分布（安全 / 风格 / 测试 / 架构）
3. 如果有重复出现的同类问题（同一类型出现 ≥3 次）：
   a. 用 tech-review 检查是否有更好的行业做法
   b. 起草改进提案（改 CLAUDE.md 规则 / 加 Hook / 升级配置）
4. 输出健康趋势报告：

   📈 健康趋势（过去 7 天）
   - 总审查数：N
   - 问题类型分布：[类型]：[次数]
   - 重复问题：[类型] 出现 N 次 → 建议改进 [方案]
   
5. 询问你的意见：
   "检测到 [问题] 反复出现，建议 [方案]，是否执行？"
```

### 适用场景

- 项目已运行一段时间，开始出现模式化问题
- 规则需要随着团队经验积累而持续优化
